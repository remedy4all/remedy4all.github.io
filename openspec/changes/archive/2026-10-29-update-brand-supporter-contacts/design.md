## Context
The supplied SVGs (`remedy-logo-proposal4-light.svg`, `-dark.svg`) are the same whole PDF page
cropped by `viewBox`. Analysis of the files shows that **the logo itself is not vector paths**.
In both crops the visible logo is an embedded, opaque RGB PNG inside a clip rectangle:
`source-5`, 988 x 506, light, with cream `rgb(246,247,240)` baked in; and `source-8`, 994 x 444,
dark, with navy `rgb(46,58,89)` baked in. The vector content of the page (glyphs, swatches, rules)
lies outside the view and is not the logo. REQ-REMD-003 requirement 8 ("the logo is outlined
paths") does not hold for these files.

## Decisions
- **Use the embedded PNGs as they are, cropped to the artwork.** Extract each PNG and crop it to
  the bounding box of its non-background pixels plus a margin. Every pixel inside is kept
  unchanged: no redrawing, recolouring or re-typesetting. Cropping removes the stray page
  fragments and the surrounding page.
- **"No background rectangle" by matching the surface exactly, not by removing it.** Making the
  background transparent would mean recomputing the anti-aliased edge pixels, which the
  "taken as it is" constraint rules out. Instead each logo sits on a surface of exactly its baked-in
  colour: the header and page background are `#F6F7F0` (cream as sampled from the artwork; the
  palette reading from the PDF is `#F6F7F1`, one unit apart), and the footer band is `#2E3A59` (the
  artwork's navy; palette `#2D3A5A`). So no edge is visible.
- **Resolution.** The light crop is about 690 px wide and is shown at most 240 CSS px wide, so it
  stays sharp up to about 2.8x device pixel ratio. PNG is lossless; no resampling for the header.
- **Derived assets are generated by a script** (`scripts/build-brand-assets.py`, run with
  `uv run --script`), from the copied sources in `brand/source/`, so they can be regenerated if
  Stereotropism delivers final artwork. Outputs are committed under `public/brand/` and `public/`.
- **Favicon:** the "r" of «remedy» cropped from the dark variant (white on navy), padded to a
  square of the same navy, at 32 px and 180 px, plus `favicon.ico`. **OG image:** the dark crop
  centred on a 1200 x 630 navy canvas. Both are derived from the artwork, nothing new is drawn.
- **Palette roles** (contrast on cream `#F6F7F0`): navy `#2D3A5A` for text, headings and links
  (10.45:1); muted text `#5A6676`, a darkened slate (5.42:1), because slate `#6D7A8A` gives only
  4.06:1; slate kept for borders; blue `#3FA9F7` (2.37:1 on cream) only for non-text accents such
  as the active-nav underline and rules. In the navy footer the text is `#F9F9F9` (10.69:1) and the
  links `#D6DAE0` (8.02:1).
- **Supporter credit** sits on a white strip at the foot of the footer, because CSSA's logo is
  dark-on-transparent and would not read on navy. The visible text is the label and the company
  name; the logo is decorative inside the same link (`alt=""`), so the link's name is
  «Computer Solutions S.A.».
- **Contact fields:** `CONTACT = { email, phone, address }` in `site.config.mjs`, each placeholder
  starting `__PLACEHOLDER`. `src/lib/contact.ts` decides per field: placeholder gives
  «coming soon»; a real email gives `mailto:`; a real phone gives `tel:` (digits and a leading `+`);
  a real address is plain text. It is unit-tested directly under Node's type stripping. The general
  "details will be published soon" sentence is removed, because it would turn false once a value
  is set and each field now says it itself.

## Risks / Trade-offs
- Raster logo: sharp enough at the sizes used, but not infinitely scalable. If Stereotropism
  delivers vector artwork, rerun the asset script with it.
- Surfaces depend on matching the baked-in colours; changing the header or footer background
  would expose the rectangle. Noted in `.claude/project.md`.
